SYSTEM FLOW

Real-Estate Lead Scraping System

A web app where the user searches a ZIP code or location, the system scrapes matching real-estate data in the background, and the results are saved into the user's account — ready to browse and export.

1. What the system does

The flow is intentionally simple for the end user: type a location → start the search → get clean, saved data.

  • Search: the user enters a ZIP code or location name (city / neighborhood).
  • Scrape: the system runs the data collection in the background using Apify.
  • Save: results are stored in the user's account so they persist and stay searchable.
  • Get data: the user browses, filters, and exports the results (CSV / Excel).

2. The building blocks

① Frontend UI WHAT THE USER SEES

The web interface: a search form, a "Start" button, live progress, a results table, export buttons, and a history of past searches.

② Backend THE ENGINE

The server that sits between the UI and Apify. It receives the search, starts the scraping job on Apify, tracks it, pulls back the results, and saves them.

③ Apify DATA COLLECTION

The cloud service that performs the actual scraping (handling proxies, anti-bot, pagination, etc.) and returns the collected data as a structured dataset.

④ Database WHERE DATA LIVES

Stores the user's account, their searches, and every scraped record — so the data is permanent and independent of the scraping run.

3. How we will build the UI

The UI is a clean, single-purpose web app. Core screens:

  • Search screen: a location input (ZIP or name), a source/options panel (e.g. how deep to scrape), and a big Start Scraping button.
  • Progress view: after starting, the user sees a live status — Queued → Scraping… → Completed — with a running count of records found.
  • Results table: the saved leads in a sortable, filterable grid (filter by city, rating, has-phone, etc.).
  • Export: one click to download the current results as CSV or Excel.
  • History: a list of previous searches with their result counts and dates, so the user can reopen or re-run any of them.

Built with a modern web stack (e.g. React / Next.js + Tailwind) for a fast, responsive feel. The UI never talks to Apify directly — it only talks to our backend.

4. How the UI connects to Apify (the backend)

The backend is the bridge. When the user clicks Start Scraping, here's the chain of events on the server side:

  • Receive the request from the UI (location + options).
  • Record the search in the database with a status of RUNNING.
  • Start the scraping job on Apify by calling Apify's API with the search input. Apify replies instantly with a job ID — the scraping then runs in the cloud.
  • Wait for completion — Apify notifies the backend the moment the job finishes (via a webhook), or the backend checks the job status periodically.
  • Fetch the results — once finished, the backend downloads the dataset (all the collected records) from Apify.
  • Save & clean — the backend stores the records in the database under the user's account, removing duplicates.
  • Update the UI — the search is marked COMPLETED and the new leads appear.
Why a backend in the middle? It keeps the Apify connection (and its secret key) safe on the server, controls who can run what, and — most importantly — copies the data into the user's own database so it's saved permanently, not just sitting temporarily inside a scraping run.

6. How the user gets the data

Inside the app

  • Results appear automatically in the results table when the search completes.
  • The user can filter, sort, and search within their saved leads.
  • Every past search is kept in history and can be reopened anytime.

Out of the app

  • Export to CSV / Excel with one click — columns arranged in a clean, consistent order.
  • Because the data is saved in the database, exports are instant and don't require re-scraping.
  • Future option: push leads to a CRM or Google Sheets.

7. What happens behind a single search (timeline)

  1. User searches a ZIP / location and clicks Start.
  2. Backend kicks off the scrape on Apify and shows the user a live "Scraping…" status.
  3. Apify collects the data in the cloud and assembles it into a structured dataset.
  4. Backend pulls the dataset the moment the job finishes.
  5. Results are saved to the database under the user's account (duplicates removed).
  6. User sees & exports the finished, clean data.
